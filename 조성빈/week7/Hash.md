# 해시 테이블 (Hash Table) 및 알고리즘 정리

---

## 1. 개요

- **목적**: 데이터를 빠르게 저장하고, Key를 사용하여 Value를 즉각적으로 조회하기 위함.
- **특징**: '키(Key) - 값(Value)' 구조로 이루어져 있으며, 키에 매핑되는 인덱스 값을 통해 O(1)에 가까운 속도로 데이터를 찾을 수 있습니다.

## 2. 해시 함수 & 해싱

### 해시 함수 (Hash Function)

- Key 값을 고정된 길이의 **해시(Hash)**로 변환하는 역할을 합니다.
- 입력값의 길이에 상관없이 언제나 일정한 길이의 결과값을 반환합니다.

### 해싱 (Hashing)

- Key 값을 해싱 과정을 통해 해시 값 또는 해시코드로 변경하는 과정입니다.
- 이 해시 값이 데이터가 저장될 **저장 위치(인덱스)**가 됩니다.

### 해시 충돌 (Hash Collision)

- 서로 다른 Key가 해시 함수를 거쳤을 때 동일한 해시 값을 가지게 되는 경우를 말합니다.

## 3. 해시 테이블 (Hash Table)

- 연관 배열 구조(Associative Array)를 이용하여 Key와 Value를 저장하는 자료구조입니다.
- **작동 원리**: 해시 함수를 사용하여 인덱스를 버킷(Bucket)이나 슬롯(Slot)의 배열로 계산합니다.
- **연관 배열 구조**: 키 하나와 값 하나가 연관되어 있어, 키를 통해 연관된 값을 얻을 수 있는 구조입니다.

## 4. 해시 충돌 해결 방법

충돌이 발생했을 때 데이터를 어떻게 저장할지에 대한 두 가지 주요 전략입니다.

### 1) Separate Chaining (Open Hashing)

- **개념**: 같은 해시 값을 가진 항목들을 연결 리스트(Linked List)로 관리하는 방법입니다.
- **작동**: 충돌이 발생하면 해당 인덱스의 연결 리스트에 새로운 키-값 쌍을 추가합니다.
- **장점**: 테이블 확장이 필요 없으며 구현이 상대적으로 간단합니다.

### 2) Open Addressing (Closed Hashing)

- **개념**: 충돌 발생 시 해시 테이블 내의 다른 빈 위치를 찾아 데이터를 저장하는 방법입니다.

#### 주요 탐사 방식:

- **선형 탐사 (Linear Probing)**:
  - 충돌 시 바로 다음의 연속적인 위치를 검사하여 처음 발견한 빈 공간에 저장합니다.
- **이차 탐사 (Quadratic Probing)**:
  - 충돌 시 제곱 단위(1, 4, 9, ...)로 위치를 이동시키며 빈 공간을 찾습니다.
- **더블 해싱 (Double Hashing)**:
  - 두 개의 해시 함수를 사용합니다. 하나는 최초 인덱스를 결정하고, 다른 하나는 충돌 발생 시 이동 폭을 결정합니다.
